# Gemma-4 26B: faster cached prefill on Intel Arc Pro B70

September 6, 2026. Linux, one 32 GB Intel Arc Pro B70, Wondernuttz's custom
OpenVINO fork and matching GenAI. **This is a runtime-kernel update, not new weights.**

## Results at a glance

| Test | Previous tile | Corrected wide-query tile |
|---|---:|---:|
| 24,576 input tokens, uncached prefill | 4,841 tok/s | **5,653 tok/s (+16.8%)** |
| 6,622 input tokens, uncached prefill | 7,428 tok/s | 7,371 tok/s (-0.8%) |
| Short-prompt decode | 112.39 tok/s | 112.35 tok/s |
| Sampled peak card memory | 26.58 GiB | 26.83 GiB |

The cleaned deployment build was then rechecked at **5,667 tok/s at 24K** and
7,380 tok/s at 6,622. That is a separate confirmation run, not another matched A/B pair.
We have **not** established 6,000+ uncached PP at 24K.

The reference model is **Gemma-4 26B-A4B Heretic INT4, LUT131K export**.
All 17 recorded generated strings matched the baseline exactly in the matched pair,
including long Skyrim fact retrieval and the RP-continuity prompt. This is bounded
quality evidence, not an exhaustive intelligence or roleplay certification.

## What changed

The cached-attention kernel now has an opt-in wider query tile. Its KQ subgroup
still covers **one 16-row physical cache page**. An earlier experiment used a
generic tile with 32 K rows per subgroup against 16-row page addressing; it failed
correctness tests even with FP16 cache and was rejected.

The accepted shape is `{16, 32, 32, 32, 16, 2, 16, 2}`. Default dispatch is unchanged.
The opt-in was qualified on the discrete Xe2/B70, head-size-512 mixed/cached-prefill
path; it does not select single-token decoding or change quantization arithmetic.
Other architectures may reuse this selector internally but are not qualified here.
Rejected experiment selectors are not included in the deployment source.

This builds on the existing custom grouped-MoE lookup work and Intel/OpenVINO's
micro-SDPA and paged-attention implementation. It does not replace or take credit
for those upstream implementations.

## Reproduce the runtime profile

Build this fork's `arc-xe2-gemma4-pa-2026.4` branch with the new selector and use
compatible OpenVINO GenAI/tokenizers. Set these variables **before Python starts**:

```bash
export MOE_USE_GROUPED_GEMM_PREFILL=1
export MOE_GROUPED_BINARY_LOOKUP=1
export GEMMA_MIXED_512_TILE=wideq
```

Use PA, DQ group128, U4 KV, an 8 GiB scheduler cache allocation,
`max_num_batched_tokens=16384`, and `max_num_seqs=1`.
For benchmarking, `enable_prefix_caching=False`; use unique prompts of exactly
6,622 and 24,576 input tokens, one generated token per timing request, and report
input tokens divided by time to first token. Discard the first JIT-warmup request
and average the next two. Cold model loading/compilation is excluded.

Prefix caching can remain enabled for actual RP serving. Chimera-X26B passed
separate 24K recall, repeated-prefix and changed-fact checks with it enabled.
Do not count prefix-hit ratios as uncached prefill throughput.

For the portable Docker server, this variable requires **newly rebuilt custom
runtime wheels** containing the selector. `git pull` alone cannot upgrade the
OpenVINO library inside an existing image. This update does not publish a new
prebuilt Docker image or change the default 12B image.

## Correctness checks and limits

- Actual 26B attention geometry: 16 query heads, 8 KV heads, global head size512.
- 24 FP16/U8/U4 CPU-reference cases passed on the corrected tile: Q31/32/33/63/64/65/129,
  cached lengths34/128/255 and 16,384.
- FP16/U8 outputs were bit-identical to the original tile across all 16 paired cases.
- The original U4 tile showed run-to-run variability and once failed its CPU-reference
  tolerance. Four U4 paired cases exceeded an additional 0.002 OFF/ON difference gate.
  **That paired gate did not pass and its tolerance was not relaxed.**
- To distinguish new-kernel stability from the variable baseline, all 8 U4 shapes
  were rerun three times on the clean build: **24/24 CPU-reference passes, and
  bit-identical repeated outputs for every shape**. The baseline variability's
  underlying cause remains open; this is not a general U4 bug-fix claim.
- Full-model Heretic checks and Chimera prefix checks passed. No recorded OOM/GPU
  reset occurred during these candidate gates. This is not long-term stress certification.

The bot runtime has been updated and its loaded library hash and two HTTP response
checks verified. The profile keeps its 16K context, DQ128, batch16384, 8 GiB cache pool,
U4 KV, sampling and reasoning settings. Wider queries mainly target cached/chunked
prefill; the measured 24K improvement is not a guaranteed gain on every 16K request.
The buddy's 31B runtime is outside this rollout. StyleTune V2 remains on its prior
held profile; do not infer new approval for it or for untested fine-tunes.

B50, other GPUs, Windows, CPU, dense 12B/31B, vision/audio and model offload are
not qualified by these measurements. Repository file size is not runtime VRAM;
131K RoPE LUT coverage is not a validated usable 131K context window.

## Regression command and artifact identity

With GPU unit tests enabled and an idle test device:

```bash
GEMMA_MIXED_512_TILE=wideq ./bin/intel64/Release/ov_gpu_unit_tests \
  --device_suffix=2 --gtest_filter='local_gemma26_mixed/*'
```

Replace the device suffix with your verified device; do not run over a serving workload.
